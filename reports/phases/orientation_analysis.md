## Is the ~55% figure flat across slices?

- By year: 53.7% to 57.2%
- By tier: 54.5% to 55.8%
- By best-of: 50.6% to 58.5%

The rate stays close to ~54-58% in every slice checked, rather than swinging toward 50% in some subgroups and away from it in others. This flatness establishes that **a persistent orientation bias exists** - it is not randomly distributed across time, tier, or format. It does **not** by itself identify the mechanism producing that bias; flatness is consistent with several possible causes and is only one piece of evidence considered below.

## Skill-proxy check (DIAGNOSTIC ONLY - see warning below)

For each team (by `team_canonical`), its win rate was computed across **the entire dataset** (all matches, past and future relative to any given match) as a rough skill proxy. Of 9,742 series rows where the two teams' dataset-wide win rates differ, team1 (the lower-surrogate-id side) is the dataset-wide stronger side in **57.4%** of cases. When team1 is the dataset-wide-stronger side its actual win rate in that match is 67.9%; when team1 is the weaker side its win rate is 38.0%.

> **WARNING - diagnostic only, never a model input.** The `team1_overall_wr`/`team2_overall_wr` statistic used above is computed over the *entire* dataset, including matches that happen chronologically *after* the match being evaluated. This is a textbook lookahead/future-aware statistic and would leak target information if used as a real feature. It exists here purely to diagnose whether id-ordering correlates with an observable strength proxy - it must **never** be carried into `series_base`, `map_base`, or any feature-engineering script. Any real "team strength" feature must be rebuilt later using only strictly-prior matches (see `reports/preprocessing_rules.md`).

Result: team1 is the stronger side in 57.4% of comparable matches - noticeably above 50%, so **team1 orientation correlates somewhat with this diagnostic historical-strength proxy**. The correlation is partial, not strong (57.4% vs. an uninformative 50%), and the proxy itself is a rough, future-aware stand-in for skill, not a validated one - this result should be read as one data point, not as proof of a mechanism.

## Conclusion

Taken together, the evidence supports the following, and no more than the following:

- **A persistent team1 orientation bias exists** (~55% vs. an expected ~50% under a symmetric assignment), and it is stable across year, tier, and format rather than isolated to one slice.
- **Team1 orientation correlates somewhat with the diagnostic historical-strength proxy** computed above (team1 is the proxy-stronger side in 57.4% of comparable matches) - a partial, not strong, relationship.
- **This pattern is consistent with an upstream ordering effect** - for example, some process upstream of this dataset (bracket layout, scrape order, id-allocation order, etc.) may list or register one side before the other in a way that is not purely random. This is a plausible explanation offered for context, not a demonstrated one.
- **The exact cause cannot be established from this dataset.** There is no column recording how or why `team_id`s were assigned, no access to the original scrape/bracket process, and no independent way to test alternative explanations (e.g. a genuine but small skill correlation with registration timing, versus a pure listing artifact) against each other. This analysis stops at documenting the bias and one supporting correlation, not at proving its origin. No raw data was changed to investigate this.

## Recommendation for future modelling (not built in this phase)

Regardless of the unresolved cause, this orientation signal should be **eliminated from modelling** rather than left for a model to potentially learn as a spurious `team1`-side prior:

- **Difference features**: engineer features as `stat_team1 - stat_team2` (or ratios) rather than separate `team1_*`/`team2_*` columns, so the model cannot learn a spurious `team1`-side prior.
- **Deterministic train-time side-swapping / mirrored augmentation**: for each training row, optionally also add the mirrored row (`team1`/`team2` swapped, all difference features negated, target flipped: `1 - team1_series_win`) so the training distribution is exactly side-balanced.
- Whichever approach is used, it must be applied consistently at both train and inference time, and documented before any model-selection work begins in a later phase.
