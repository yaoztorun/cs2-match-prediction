# Phase 6B - Known-Map Random Forest Tuning (TRAIN-only chronological CV)

Generated by `scripts/models/map_random_forest_tuning_v1.py`. **36 candidates** (8 deterministic anchors + 28 `RandomState(42)` draws) x 4 expanding-window folds from `data/modeling/map_cv_folds_v1.csv`.

**Target: `team1_map_win` - the winner of one specific, user-selected map.** This is not the pre-veto series task, and these numbers are not comparable with the series models' accuracies.

## Why the main validation partition cannot have influenced this

This script never opens `data/modeling/map_split_v1.csv`. It reads only the Phase 6A CV manifest, which by construction contains **TRAIN match_ids only** (independently re-verified in `scripts/validate_phase6b.py`). The 1,129-map main validation partition and the 1,427-map TEST partition are therefore structurally absent from candidate selection.

## Fixed protocol

- `n_estimators = 400` for every candidate - the search budget goes to the structural parameters, not to tree count.
- `random_state = 42`, `n_jobs = -1`, `bootstrap = True`.
- Each fold's TRAIN block is mirrored (original + side-swapped) and the preprocessing (median imputation) is fit on that augmented fold-train **only**. Fold validation is original and unmirrored.
- TRAIN metrics are reported on the **original unmirrored** fold-train rows, so train-validation gaps stay comparable across phases.
- Transformed dimension: **106** columns from 95 raw predictive inputs (62 directional + 18 continuous symmetric + 12 binary symmetric + 9 map dummies + 2 bestOf dummies + 3 tier dummies).

## Selection rule (fixed before the search ran)

1) PRIMARY: lowest mean chronological-CV log loss. 2) EQUIVALENCE: candidates within 0.002 of the best mean log loss are treated as essentially equivalent. 3) highest mean ROC-AUC. 4) lowest mean Brier. 5) highest mean accuracy. 6) lower log-loss standard deviation. 7) COMPLEXITY (deterministic): lower max_depth -> higher min_samples_leaf -> higher min_samples_split -> lower effective max_features fraction -> candidate_id. Accuracy is never optimized alone; fit time never participates in selection.
